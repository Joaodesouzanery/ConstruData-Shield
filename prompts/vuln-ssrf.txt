## SSRF Patterns to Analyze

1. **Direct SSRF**: User-controlled URLs in server-side HTTP requests
2. **Blind SSRF**: Server makes requests but response not returned to user
3. **Partial SSRF**: User controls part of the URL (path, host, port)
4. **SSRF via Redirects**: Following redirects to internal resources
5. **DNS Rebinding**: Bypassing IP-based allowlists via DNS tricks
6. **Cloud Metadata**: Accessing cloud provider metadata endpoints (169.254.169.254)

## Analysis Method

For each potential SSRF point:
1. **Identify user-controlled URLs**: Find where users can specify URLs/hosts
2. **Check validation**: Are URLs validated? Allowlists or denylists?
3. **Check redirect following**: Does the application follow HTTP redirects?
4. **Assess internal access**: What internal services could be reached?
